## 🎯 概述

本文档描述 AI-Trader 平台的前端界面新架构。新架构采用清晰的功能分区和模块化设计，提供更直观的用户体验，使用户能够高效地管理交易策略、监控平台服务并分析交易表现。

### 设计原则

- **清晰导航**：功能入口明确，层级结构简单
- **模块化设计**：每个功能模块独立，便于维护和扩展
- **数据可视化**：直观展示策略表现和平台状态
- **模式区分**：明确区分回测、模拟盘、实盘三种运行模式
- **实时监控**：提供策略运行状态实时监控和进度显示
- **日志追踪**：完整的AI决策过程记录和展示

### 核心组件

#### 1. 前端界面层 (`docs/`)

**主要页面**:
- `home.html` - 平台首页，提供策略管理和服务状态入口
- `strategies.html` - 策略管理页面，显示策略列表和创建新策略
- `strategy-detail.html` - 策略详情页面，包含配置管理、资产演变、投资组合分析
- `services.html` - 平台服务状态页面，监控 MCP 和 API 服务

**技术栈**:
- 纯 HTML/CSS/JavaScript
- Chart.js 用于数据可视化
- 通过 HTTP API 与后端通信

#### 2. API 服务层

**策略 API** (`platform/strategy_api.py`, 端口 8005):
- 策略管理：创建、删除、列表、配置保存/加载
- 策略运行：启动回测/模拟盘/实盘
- **运行状态监控**：实时检查策略运行状态（运行中/已完成/失败）
- **进程管理**：跟踪策略执行进程，提供进程ID和启动时间
- 结果查询：获取资产演变、投资组合、日志数据
- **AI思考日志**：按日期查询AI决策过程的详细日志
- 服务管理：MCP 服务启动/停止、状态查询

**配置 API** (`config_api.py`, 端口 8004):
- 配置管理：读取/保存默认配置
- Prompt 管理：读取/保存系统提示词
- 进程管理：重启 main.py、检查运行状态

#### 3. 业务逻辑层

**策略管理器** (`platform/strategy_manager.py`):
- 策略创建和管理
- 配置文件的读写（JSON 格式）
- Prompt 文件的管理（Python 格式）
- 策略数据路径管理

**运行管理器** (`platform/run_manager.py`):
- 策略执行流程管理
- 运行模式切换（回测/模拟盘/实盘）
- 环境变量和配置文件的准备
- 与 main.py 的集成
- **运行状态检查**：使用 `psutil` 检查进程是否运行
- **进程信息管理**：保存进程ID、启动时间到 `logs/{strategy_id}_{mode}_process.json`
- **实时日志获取**：从日志文件读取最新AI思考日志并返回给前端
- **结果数据加载**：从策略数据目录加载资产演变、投资组合、交易数据

**服务管理器** (`platform/service_manager.py`):
- MCP 服务进程管理
- 服务状态监控
- 服务启动/停止控制

#### 4. MCP 工具服务层

**MCP (Model Context Protocol) 服务** (`agent_tools/`):

| 服务 | 文件 | 端口 | 功能 |
|------|------|------|------|
| 交易工具 | `tool_trade.py` | 8002 | 买入/卖出股票、持仓管理 |
| 价格工具 | `tool_get_price_local.py` | 8003 | 历史价格查询、实时价格获取 |
| 搜索工具 | `tool_jina_search.py` | 8001 | 市场信息搜索、新闻查询 |
| 数学工具 | `tool_math.py` | 8000 | 金融计算、数据分析 |

**启动方式**: `agent_tools/start_mcp_services.py` 统一管理所有 MCP 服务

#### 5. 核心执行层

**主程序** (`main.py`):
- AI Agent 的启动和调度
- 交易日历管理
- 多模型并发执行
- 交易记录和日志生成

**AI 代理** (`agent/base_agent/base_agent.py`):
- 基于 LangChain 的 AI Agent 实现
- MCP 工具集成
- 自主决策和交易执行
- 思考过程记录

#### 6. 数据存储层

**配置文件** (`configs/`):
```
configs/
├── default_config.json          # 默认配置
├── strategies/                   # 策略配置目录
│   └── {strategy_id}/
│       ├── base_config.json     # 基础配置
│       ├── backtest_config.json # 回测配置
│       ├── simulate_config.json # 模拟盘配置
│       ├── real_config.json     # 实盘配置
│       └── prompts/             # Prompt 文件
│           ├── base_prompt.py
│           ├── backtest_prompt.py
│           ├── simulate_prompt.py
│           └── real_prompt.py
```

**交易数据** (`data/`):
```
data/
├── merged.jsonl                 # 统一价格数据
├── strategies/                  # 策略数据目录
│   └── {strategy_id}/
│       ├── backtest/            # 回测数据
│       │   └── agent_data/
│       │       ├── position/    # 持仓记录
│       │       └── log/         # AI 思考日志
│       ├── simulate/            # 模拟盘数据
│       └── real/                # 实盘数据
└── agent_data/                  # 旧格式数据（兼容）
```

**日志文件** (`logs/`):
- `mcp_services.log` - MCP 服务日志
- `strategy_api.log` - 策略 API 日志
- `config_api.log` - 配置 API 日志
- `frontend.log` - 前端服务器日志
- `{strategy_id}_{mode}_process.json` - 策略运行进程信息（进程ID、启动时间、状态）

### 服务端口分配

| 服务 | 端口 | 说明 |
|------|------|------|
| 前端服务器 | 8000 | HTTP 静态文件服务 |
| MCP 数学工具 | 8000 | 数学计算服务 |
| MCP 搜索工具 | 8001 | 信息搜索服务 |
| MCP 交易工具 | 8002 | 交易执行服务 |
| MCP 价格工具 | 8003 | 价格查询服务 |
| 配置 API | 8004 | 配置管理 API |
| 策略 API | 8005 | 策略管理 API |

**注意**: MCP 数学工具和前端服务器都使用端口 8000，但它们是不同的服务，不会同时运行。

## 📊 策略管理界面

### 功能概述

策略管理界面是策略的列表视图，提供策略的创建、查看和管理功能。

### 界面布局

```
┌─────────────────────────────────────────────────┐
│  策略管理                           [+ 创建新策略] │
├─────────────────────────────────────────────────┤
│                                                 │
│  ┌─────────────────────────────────────────┐   │
│  │ 策略名称: 保守型策略                      │   │
│  │ 描述: 低风险、稳定收益的策略               │   │
│  │ 状态: 运行中 | 最后更新: 2025-11-04      │   │
│  │ [查看详情] [运行回测] [运行模拟] [运行实盘]│   │
│  └─────────────────────────────────────────┘   │
│                                                 │
│  ┌─────────────────────────────────────────┐   │
│  │ 策略名称: 激进型策略                      │   │
│  │ 描述: 高风险、高收益的策略                 │   │
│  │ 状态: 设计中 | 最后更新: 2025-11-03      │   │
│  │ [查看详情] [编辑] [删除]                  │   │
│  └─────────────────────────────────────────┘   │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 功能模块

#### 1. 策略列表展示

- **显示内容**：
  - 策略名称
  - 策略描述
  - 当前状态（设计中/回测中/模拟盘中/实盘中/已归档）
  - 最后更新时间
  - 快速操作按钮

- **列表功能**：
  - 搜索：按策略名称搜索
  - 筛选：按状态筛选（设计中/运行中/已归档）
  - 排序：按创建时间、更新时间、状态排序
  - 分页：支持大量策略的分页显示

#### 2. 创建新策略

- **入口**：页面右上角 "+ 创建新策略" 按钮
- **创建流程**：
  1. 输入策略名称和描述
  2. 选择基础 Prompt 模板（可选）
  3. 配置初始参数（初始资金等，注意：日期范围仅在回测配置中设置）
  4. 确认创建

- **创建后**：
  - 自动跳转到策略详情页面的"配置管理"模块
  - 可以继续完善配置

#### 3. 删除策略

- **入口**：策略卡片上的"删除"按钮
- **删除流程**：
  1. 点击"删除"按钮
  2. 弹出确认对话框（显示策略名称和警告信息）
  3. 确认删除后，删除策略配置和数据文件
  4. 更新策略列表

- **注意事项**：
  - ⚠️ 删除操作不可恢复，会删除策略的所有配置和数据
  - ⚠️ 如果策略正在运行，需要先停止运行才能删除
  - 删除前会显示策略的基本信息（创建时间、运行状态等）

### 策略卡片操作

每个策略卡片提供以下操作：

- **查看详情**：进入策略详情界面
- **运行回测**：快速启动回测（使用默认配置）
- **运行模拟**：快速启动模拟盘（使用默认配置）
- **运行实盘**：启动实盘交易（需要确认）
- **编辑**：编辑策略基本信息
- **删除**：删除策略（需要确认，⚠️ 不可恢复）

#### 删除策略功能详解

- **删除按钮位置**：策略卡片右下角，使用红色样式
- **删除确认**：
  - 显示策略名称和创建时间
  - 警告：此操作将删除策略的所有配置和数据，且不可恢复
  - 如果策略正在运行，提示先停止运行
- **删除范围**：
  - 策略配置文件（`configs/strategies/{id}/`）
  - 策略运行数据（`data/strategies/{id}/`）
  - 策略的所有模式数据（回测、模拟、实盘）

### 模块一：配置管理

#### 功能概述

配置管理模块允许用户查看和修改策略的各项配置参数。

#### 界面内容

```
配置管理
├─ Prompt 管理
│  ├─ 基础 Prompt（所有模式共用）
│  ├─ 回测 Prompt（可选，覆盖基础 Prompt）
│  ├─ 模拟盘 Prompt（可选，覆盖基础 Prompt）
│  └─ 实盘 Prompt（可选，覆盖基础 Prompt）
│
├─ Agent 配置参数（所有模式共用）
│  ├─ max_steps: 最大推理步数
│  ├─ max_retries: 最大重试次数
│  ├─ base_delay: 基础延迟时间
│  └─ initial_cash: 初始资金
│
├─ 模型配置（所有模式共用）
│  ├─ 选择使用的 AI 模型
│  ├─ 模型 API 配置
│  └─ 模型启用状态
│
└─ 模式特定配置
   ├─ 回测配置
   │  ├─ 交易日期范围（仅回测使用）
   │  │  ├─ 开始日期
   │  │  └─ 结束日期
   │  └─ 历史数据设置
   │
   ├─ 模拟盘配置
   │  ├─ Moomoo 模拟账户设置
   │  └─ 自动启动设置（是否在启动时自动开始交易）
   │
   └─ 实盘配置
      ├─ Moomoo 实盘账户设置
      ├─ 风险控制参数
      │  ├─ max_daily_loss: 最大单日亏损
      │  ├─ max_position_size: 单只股票最大仓位
      │  └─ stop_loss: 止损比例
      └─ 自动启动设置（是否在启动时自动开始交易）
```

#### 操作功能

- **加载配置**：从文件加载当前配置（按当前选择的模式）
- **保存配置**：保存修改后的配置（保存到对应模式的配置）
- **重置**：恢复默认配置
- **验证**：检查配置的有效性
- **重启服务**：修改配置后，需要重启服务才能生效（显示重启按钮）

#### 配置管理模式

配置管理界面顶部显示模式选择器，允许用户分别为不同模式配置：

1. **基础配置**（所有模式共用）
   - Agent 参数
   - 模型配置
   - 基础 Prompt

2. **回测配置**（仅回测模式）
   - 交易日期范围（必填）
   - 历史数据设置

3. **模拟盘配置**（仅模拟盘模式）
   - Moomoo 模拟账户设置
   - 自动启动设置

4. **实盘配置**（仅实盘模式）
   - Moomoo 实盘账户设置
   - 风险控制参数
   - 自动启动设置

#### 配置保存和生效

- **保存配置**：点击"保存配置"按钮后
  - 配置保存到对应模式的文件
  - 显示"配置已保存，需要重启服务才能生效"提示
  - 显示"重启服务"按钮

- **重启服务**：
  - 点击"重启服务"按钮
  - 确认对话框：重启将停止当前运行的任务
  - 重启后，新配置生效
  - 如果策略正在运行，会先停止再重启

- **配置生效时机**：
  - 修改配置后需要重启服务才能生效
  - 正在运行的策略不会自动应用新配置
  - 新启动的策略会使用最新配置

### 模块二：资产演变

#### 功能概述

资产演变模块可视化展示策略在不同运行模式下的资产价值变化曲线和关键指标。

#### 界面布局

```
资产演变
```

#### 运行状态监控系统

**功能概述**: 实时监控策略运行状态，提供进度显示和实时日志输出

**状态容器组成**:
```
┌─────────────────────────────────────────┐
│ ⏳ 回测运行中...                    [停止] │
│ 策略正在运行中...                        │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │ 进度条（60%）
│                                         │
│ [实时日志显示区域]                       │
│ [10:30:15] AI正在分析市场趋势...        │
│ [10:30:18] 正在查询股票价格...          │
│ [10:30:20] 准备执行买入操作...          │
└─────────────────────────────────────────┘
```

**状态类型**:
- **运行中** (⏳): 进程存在且运行中，显示60%进度条（带动画）
- **已完成** (✅): 进程结束且有结果文件，显示100%进度条（绿色）
- **失败** (❌): 进程结束但无结果文件，显示100%进度条（红色）
- **未启动** (⏸️): 无进程信息文件，进度条0%

**状态监控机制**:
- **轮询频率**: 每2秒检查一次状态
- **触发时机**: 
  - 策略启动后立即开始
  - 页面加载时检查是否有正在运行的策略
- **停止条件**: 
  - 策略运行完成
  - 策略运行失败
  - 用户离开页面

**实时日志显示**:
- **日志来源**: 从 `data/strategies/{id}/{mode}/agent_data/log/{date}/log.jsonl` 读取
- **更新机制**: 每次状态检查时读取最新日志条目
- **显示格式**: `[时间戳] 日志内容`
- **去重机制**: 避免重复显示相同日志
- **自动滚动**: 新日志自动滚动到底部

**进度条动画**:
- **运行中**: 脉冲动画（opacity 1 → 0.6 → 1）
- **已完成**: 停止动画，显示100%绿色
- **失败**: 停止动画，显示100%红色

#### AI 思考日志功能

**功能位置**：资产演变模块下方

**功能说明**：
- **日期选择**：下拉菜单选择要查看的日期
- **日志展示**：
  - 显示该日期所有 AI 对话记录
  - 包括用户查询、AI 回复、工具调用结果
  - 按时间顺序展示，最新记录在下方
  - 支持代码高亮（Markdown 代码块）
  - 支持格式化显示（换行、缩进等）

**日志内容**：
- **时间戳**：每条日志的精确时间
- **模型标识**：显示使用的 AI 模型（signature）
- **对话记录**：
  - 用户消息（蓝色标识）

  - 决策依据

**使用场景**：

- **审计**：实盘交易时，记录完整的决策过程用于审计

**日志格式**：

**API 端点**：

- `GET /api/strategies/{strategy_id}/logs/{mode}/{date}` - 获取指定日期的日志内容

## 🔄 数据流设计

### 前端数据请求流程

```
用户操作
  ↓
前端界面
  ↓
API 请求 (Strategy API / Config API)
  ↓
后端服务
  ↓
数据存储 (配置文件 / 数据文件)
  ↓
返回数据
  ↓
前端展示
```

### 数据来源

#### 配置数据
- **来源**：`configs/strategies/{strategy_id}/`
- **API**：`GET /api/strategies/{id}/config/{mode}`
- **更新**：`POST /api/strategies/{id}/config/{mode}`

#### 运行结果数据
- **回测数据**：`data/strategies/{strategy_id}/backtest/agent_data/`
- **模拟盘数据**：`data/strategies/{strategy_id}/simulate/agent_data/`
- **实盘数据**：`data/strategies/{strategy_id}/real/agent_data/`

#### 服务状态数据
- **来源**：`ServiceManager` 检查服务进程
- **API**：`GET /api/services/status`

### 数据更新机制

1. **配置更新**：用户修改 → API 保存 → 文件更新 → 前端刷新
2. **运行结果更新**：策略运行 → 数据写入 → 前端轮询或手动刷新
3. **服务状态更新**：自动轮询（5秒）或手动刷新
4. **运行状态更新**：策略运行中 → 前端每2秒轮询状态API → 更新进度和日志

### 策略执行数据流

```
用户点击运行按钮
    ↓
确认对话框
    ↓
POST /api/strategies/{id}/run/{mode}
    ↓
运行管理器 (run_manager.py)
    ├─ 检查MCP服务状态
    ├─ 准备配置文件和环境变量
    ├─ 启动 main.py 子进程
    └─ 保存进程信息到 logs/{id}_{mode}_process.json
    ↓
核心执行层 (main.py + BaseAgent)
    ├─ 执行交易逻辑
    ├─ 写入交易数据到 data/strategies/{id}/{mode}/
    └─ 写入AI思考日志到 data/strategies/{id}/{mode}/agent_data/log/
    ↓
数据存储层 (文件系统)
    ↓
返回运行信息 (JSON)
    ↓
前端显示状态容器并开始监控
```

### 运行状态监控数据流

```
前端状态轮询 (每2秒)
    ↓
GET /api/strategies/{id}/status/{mode}
    ↓
API 服务层 (strategy_api.py)
    ↓
运行管理器 (run_manager.py)
    ├─ 读取进程信息文件 logs/{id}_{mode}_process.json
    ├─ 使用 psutil 检查进程是否运行
    ├─ 读取最新日志文件获取最新日志内容
    └─ 检查结果数据文件是否存在
    ↓
返回状态信息 (JSON)
    ├─ is_running: 是否正在运行
    ├─ status: 状态 (running/completed/failed)
    ├─ latest_log: 最新日志内容
    └─ message: 状态消息
    ↓
前端更新显示
    ├─ 更新进度条
    ├─ 显示实时日志
    └─ 更新状态图标和文本
```

## 🔧 技术架构详解

### 1. 运行状态监控系统

#### 后端实现

**进程跟踪机制**:
- 使用 `psutil` 库检查进程是否运行
- 进程信息保存在 `logs/{strategy_id}_{mode}_process.json`
- 包含进程ID、启动时间、配置文件路径

**状态检查流程**:
```python
1. 读取进程信息文件
2. 使用 psutil.Process(pid) 获取进程对象
3. 检查 process.is_running()
4. 验证进程命令行包含 "main.py"
5. 读取最新日志文件获取最新日志内容
6. 检查结果数据文件是否存在
7. 返回状态信息
```

**状态判断逻辑**:
- `is_running = true`: 进程存在且运行中
- `status = "completed"`: 进程结束且有结果文件
- `status = "failed"`: 进程结束但无结果文件
- `status = "not_started"`: 无进程信息文件
- `status = "error"`: 检查过程中出错（如 psutil 未安装）

**日志读取机制**:
- 从 `data/strategies/{id}/{mode}/agent_data/log/` 目录查找
- 按日期排序，获取最新日期目录
- 读取 `log.jsonl` 文件的最后一行
- 解析 JSON，提取最新消息内容
- 截断过长内容（超过200字符）

#### 前端实现

**状态容器组件**:
- 状态图标：⏳ 运行中、✅ 已完成、❌ 失败、⏸️ 未启动
- 状态文本：动态显示当前状态描述
- 进度条：CSS 动画，运行中显示脉冲效果
- 日志区域：固定高度，自动滚动

**轮询机制**:
```javascript
// 每2秒检查一次状态
setInterval(async () => {
    await checkRunStatus(mode);
}, 2000);
```

**状态更新逻辑**:
- 运行中：更新进度条到60%，显示最新日志
- 已完成：进度条到100%（绿色），3秒后自动隐藏
- 失败：进度条到100%（红色），显示错误信息
- 未启动：隐藏状态容器

**日志显示优化**:
- 日志去重：检查日志内容是否已显示
- 时间戳格式化：显示本地时间
- 自动滚动：新日志追加后滚动到底部
- 格式化显示：使用等宽字体，保持可读性

### 2. 进程管理机制

#### 进程信息保存

**文件格式** (`logs/{strategy_id}_{mode}_process.json`):
```json
{
  "strategy_id": "strategy_20251104_120000",
  "mode": "backtest",
  "process_id": 12345,
  "config_file": "configs/runtime_strategy_20251104_120000_backtest.json",
  "start_time": 1699123456.789,
  "status": "running"
}
```

**保存时机**:
- 策略启动时立即保存
- 包含进程ID、启动时间、配置文件路径

**更新时机**:
- 状态检查时更新状态字段（如果需要）
- 策略完成后保留文件（用于历史记录）

#### 进程检查实现

**检查步骤**:
1. 读取进程信息文件
2. 获取进程ID
3. 使用 `psutil.Process(pid)` 获取进程对象
4. 检查 `process.is_running()`
5. 验证进程命令行：`"main.py" in cmdline`
6. 返回检查结果

**错误处理**:
- `psutil.NoSuchProcess`: 进程不存在，认为已结束
- `psutil.AccessDenied`: 权限不足，跳过检查
- `psutil` 未安装：返回错误状态，提示安装

- 日志加载失败：显示"加载失败"提示
